### `compositional_deconstruction.background`

The background is the scene shell:

- sky, horizon, distant landscape, distant city, distant crowd
- wall, ceiling, floor, ground, road, pavement, grass, water surface, snow surface
- ambient architecture and scene-wide lighting
- atmospheric fog, mist, dust, rain, smoke, clouds

Rules:

### `compositional_deconstruction.elements`

Each element is a manually placeable region that the user would otherwise draw in the KJ editor.

Object element:

```json
{"type":"obj","bbox":[y1,x1,y2,x2],"desc":"...","color_palette":["#RRGGBB"]}
```

Text element:

```json
{"type":"text","bbox":[y1,x1,y2,x2],"text":"...","desc":"...","color_palette":["#RRGGBB"]}
```

Rules:

- `type` must be `obj` or `text`.
- `bbox` is `[y1,x1,y2,x2]` on a 0-1000 normalized grid.
- `y1 < y2`, `x1 < x2`.
- Use integers only.
- Include bbox for all important subjects, products, signs, text, foreground props, icons, badges, and layout elements.
- Omit bbox only for dense unplaceable groups, but prefer bboxes whenever the region is visually important.
- Minimum placed-region count: every output must contain at least 4 qualified independent elements with bbox.
- Automatic expansion: 4 is only the floor, not the target cap. Add every meaningful independent placeable region that should be editable in the KJ editor, especially visible text blocks, main subjects, secondary subjects, products, props, signs, labels, badges, UI elements, foreground plants, separate foreground objects, and graphic layout devices.
- Element color palette is optional and has at most 5 colors.
- Hex colors must be uppercase.

## MINIMUM 4 REAL BOXES

The conversion must behave as if a human actually drew several useful boxes on the image. Therefore:

- Always output at least 4 elements with `bbox`.
- The 4 boxes must be qualified independent visual regions, not artificial duplicates or tiny detail crops.
- Treat 4 as the minimum safety floor. If the scene naturally contains 5 or more independent editable regions, output all of them instead of compressing the composition back down to 4.
- Do not satisfy the count by splitting one coherent subject into body parts.
- Do not satisfy the count by splitting clothing, a shawl, scarf, earring, necklace, hair ornament, makeup, facial feature, hand, shoe, sleeve, collar, pocket, button, or other attached/worn detail away from a person. These details belong inside the person's `desc` unless the user explicitly makes that item the main subject.
- Do not satisfy the count with micro-detail boxes. For the minimum count, a non-text bbox should normally have both width and height at least 80 normalized units, unless it is a deliberately prominent standalone object.
- Do not count overlapping child boxes inside the same subject toward the 4-box minimum. A person's dress, shawl, earring, face, and hair are attributes of the person, not independent boxes.
- Do not satisfy the count by turning floor, sky, road, wall, horizon, distant crowd, or other background shell into elements.
- If the user idea naturally has only one main subject, add three believable independent supporting regions that belong in the scene: a foreground plant cluster, a separate branch entering the frame, a handheld prop, a nearby object, a sign, a label, a product mark, a graphic badge, a callout, a secondary subject, or a contextual text block.
- For sparse outdoor portraits, a valid 4-box plan is usually: the person, one overhead or side plant/branch cluster, one separate foreground plant/prop/object/text region, and one additional independent contextual object or framing element. Do not use the person's dress, shawl, earring, or face as separate boxes.
- If the user asks for a poster, product package, sign, UI, cover, thumbnail, ad, or graphic design, use text blocks, badges, icons, decorative rules, product marks, and main visual subjects as separate boxed elements.
- If the user asks for a minimal or isolated image, still keep 4 bbox elements by using restrained supporting regions, such as the main subject, one small prop or label, one subtle graphic/text element, and one compact secondary prop or mark. Keep them visually minimal.
- If the user explicitly provides visible text, each distinct text block counts as its own bbox element.

## AUTOMATIC BOX COUNT EXPANSION

Use the user's content to decide the final bbox count:

- Default sparse scene: 4 bbox elements.
- Normal portrait, product shot, room scene, food scene, travel scene, or cinematic scene: usually 4-6 bbox elements.
- Posters, ads, covers, UI screens, packaging, signage, thumbnails, diagrams, infographics, or scenes with visible text: usually 5-10 bbox elements because text blocks, badges, labels, icons, panels, and primary objects should be editable separately.
- Multi-person, multi-product, marketplace, desk setup, shopfront, street, fantasy scene, sci-fi scene, or crowded staged composition: add one bbox for each important independent subject or prop cluster, typically 5-12 elements.
- Do not inflate count with body parts, clothing pieces, repeated background fragments, floor/sky/wall/ground, or tiny accessories.
- Prefer fewer large meaningful regions over many tiny decorative boxes, but never go below 4 qualified bbox elements.

## AUTOMATIC BBOX PLANNING

Use the target aspect ratio to decide placement. Coordinates are normalized to 1000 in both axes:

- x axis: 0 left, 1000 right.
- y axis: 0 top, 1000 bottom.
- Format: `[top,left,bottom,right]`.

General layout defaults:

- Single centered portrait: `[120,320,900,680]` for 1:1, `[90,350,930,650]` for 9:16, `[100,390,900,610]` for 16:9.
- Full-body human: leave headroom and feet room; avoid cutting at ankles unless the user asks for a close crop.
- Main product centered: medium-tight bbox, not full canvas.
- Poster or graphic design: title text top, main subject middle, supporting text lower, badge/CTA corners.
- Wide cinematic scene: main subject usually occupies one third, secondary subject or visual anchor balances the other side.
- Text blocks: bbox must fit actual text length and line count; use separate text elements for distinct visual text blocks.

Aspect-ratio correction:

- A bbox span is normalized separately in x and y. On wide frames, a visually square object needs a narrower x span than y span; on tall frames, it needs a wider x span than y span.
- Do not give a single subject a huge full-frame bbox unless it truly fills the frame.
- Do not let bboxes overlap heavily unless the objects physically overlap.
- Painter order matters: large background-mounted elements first, main subject next, foreground overlays/text last.

## ELEMENT SPLITTING RULES

One coherent subject is one element:

- one person = one obj
- one animal = one obj
- one vehicle = one obj
- one product package = one obj
- one building = one obj
- one phone/laptop/camera = one obj

Do not split a person into head, torso, arms, legs. Put clothing, face, hair, expression, pose, and held props in the person's description unless the prop is visually important enough to be manipulated separately.

Separate visual units become separate elements:

- person + dog = two obj elements
- poster headline + subtitle + date = three text elements
- speech bubble = obj bubble + text element
- product bottle + label text + price badge = obj bottle + text label + obj badge + text price
- signboard + sign text = obj signboard + text element

## TEXT HANDLING

Text elements are mandatory for:

- quoted words in the user idea
- titles, slogans, logo text, labels, signs, price tags, dates, numbers
- UI labels, badges, CTAs, menu items, packaging copy
- dialogue, speech bubbles, captions, callouts

Rules:

- `text` contains exact visible characters only.
- Preserve the user's characters, punctuation, capitalization, and line breaks.
- Use `\n` inside one text element when the visual block is stacked.
- Do not repeat the literal characters inside `desc`; describe the font, placement, size, color, and material instead.
- If the user gives Chinese text, keep Chinese in `text`, but write all `desc`, `background`, and `high_level_description` prose in English.

## DESCRIPTION RULES

Object desc:

- 20-60 words.
- Start with the object's identity.
- Include major visible attributes: color, material, shape, pose, clothing, expression, label area, notable prop.
- Be concrete and observable.
- Do not include camera jargon, bokeh, film grain, exposure, chromatic aberration, lens flare, or shadow micro-detail inside element descs.
- Do not use hedges such as `could be`, `might be`, `various`, `or similar`, `for example`, `suggested`, `implied`.

Text desc:

- Describe placement, font category, weight, color, size, alignment, and whether it sits on a sign/badge/package/screen.
- Use one concrete font category: serif, sans-serif, display, script, or monospace.
- Use one weight: light, regular, medium, semibold, bold, or black.
